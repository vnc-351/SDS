# CampusFix Database

CampusFix uses **PostgreSQL**, accessed from Python with `psycopg` 3. 

## Connection and configuration

| Setting | Where | Purpose |
|---|---|---|
| `DATABASE_URL` | `.env` | App database, for example `postgresql://postgres:PASSWORD@localhost:5432/campusfix` |
| `TEST_DATABASE_URL` | `.env` | Test database. The name must end with `_test`. |

`config.py` reads `DATABASE_URL` into `DATABASE` and stops with a clear error if it is missing. Special characters in the password must be percent-encoded in the URL (`@` becomes `%40`).

Create both databases once, in `psql`:

```sql
CREATE DATABASE campusfix;
CREATE DATABASE campusfix_test;
```

## How the app uses the database

- **One connection per request.** `get_db()` opens a connection the first time a request needs it and stores it on Flask's `g`. `close_db()` closes it when the request ends. A connection closed with unfinished work rolls that work back.
- **Rows are dictionaries.** Connections use `row_factory=dict_row`, so code writes `row["title"]` and `row["count"]`.
- **Explicit commits.** Routes call `conn.commit()` after writes. A request that fails halfway is rolled back automatically.
- **Parameterised queries.** All values go through `%s` placeholders. Nothing from a user is ever put into SQL text.
- **Schema on startup.** `init_app()` runs `init_db()` every time the app starts. All statements use `IF NOT EXISTS`, so it is safe to run repeatedly. A PostgreSQL advisory lock stops several workers that start together from creating tables at the same moment.
- **Admin bootstrap.** If `ADMIN_EMAIL` and `ADMIN_PASSWORD` are set, `ensure_default_admin()` creates that admin. It never promotes an existing student account, and it logs a warning instead of crashing.

## Tables

### `users`

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER, identity | Primary key, generated by the database |
| `name` | TEXT | Required |
| `email` | TEXT | Required, **unique**, stored in lower case |
| `password_hash` | TEXT | Werkzeug hash, never the password |
| `role` | TEXT | `student` (default) or `admin` |
| `created_at` | TIMESTAMP | Defaults to the current time |

### `complaints`

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER, identity | Primary key. The ticket number shown to users is derived from it. |
| `user_id` | INTEGER | Foreign key to `users(id)`, required |
| `title`, `category`, `location`, `description` | TEXT | Required |
| `image_filename` | TEXT | Random file name inside `uploads/` |
| `status` | TEXT | `Pending` (default), `In Progress` or `Resolved` |
| `ai_category`, `ai_priority`, `ai_explanation` | TEXT | Gemini suggestion, may be empty |
| `created_at`, `updated_at` | TIMESTAMP | `updated_at` changes when the status changes |

### `status_history`

One row for every status change. When a ticket is created, its first row goes from `New` to `Pending`.

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER, identity | Primary key |
| `complaint_id` | INTEGER | Foreign key to `complaints(id)` |
| `previous_status` | TEXT | May be empty |
| `new_status` | TEXT | Required |
| `changed_by` | INTEGER | Foreign key to `users(id)` |
| `changed_at` | TIMESTAMP | Defaults to the current time |

### `complaint_votes`

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER, identity | Primary key |
| `complaint_id` | INTEGER | Foreign key to `complaints(id)` |
| `user_id` | INTEGER | Foreign key to `users(id)` |
| `vote` | INTEGER | `1` (upvote) or `-1` (downvote), enforced by a CHECK constraint |
| `created_at` | TIMESTAMP | Defaults to the current time |

A **unique constraint on `(complaint_id, user_id)`** guarantees one vote per student per issue.

### Indexes

`idx_complaints_user_id` on `complaints(user_id)` and `idx_status_history_complaint_id` on `status_history(complaint_id)`, because both columns are used in frequent lookups. Primary keys and unique constraints have their own indexes.

## Business rules stored in SQL

- **Archive rule.** A resolved ticket stays in normal lists for one day:

  ```sql
  status != 'Resolved' OR updated_at > NOW() - INTERVAL '1 day'
  ```

  The archive page shows resolved tickets whose `updated_at` is older than one day. This condition lives in `ACTIVE_TICKET_SQL` in `database.py`.
- **Ticket IDs.** `CF-00001` is `CF-` plus the complaint `id` padded to five digits (`ticket_ref()`). Admin search accepts `CF-00012`, `cf12`, `00012` and `12`.
- **Issue board score.** Upvotes minus downvotes, counted with subqueries on `complaint_votes`. Issues are ordered by score, then newest first.
- **Priority labels.** Old labels are renamed when the app starts: `Urgent` to `Critical`, `High` to `Important`, `Medium` to `Normal`. The current labels are `Critical`, `Important`, `Normal` and `Low`.

Duplicate registrations are caught with `psycopg.errors.UniqueViolation`, which also fixes the race where two people register the same email at the same moment.

## Tests and the test database

Tests run against `campusfix_test`. `tests/pg_helpers.py` provides:

- `connect()`: a plain connection for inserting and reading test data.
- `reset_db()`: creates the tables if needed, then runs
  `TRUNCATE users, complaints, status_history, complaint_votes RESTART IDENTITY CASCADE`, so every test starts empty and ids begin at 1.
- A safety check that stops the run if `TEST_DATABASE_URL` is missing, equals `DATABASE_URL`, or does not end in `_test`.
- Removal of `ADMIN_EMAIL` and `ADMIN_PASSWORD` from the environment, so tests never create the real admin.
